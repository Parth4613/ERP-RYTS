## Database

### AD-001 — Primary Keys
`bigint generated always as identity` for all tables.
UUIDv4 causes B-tree fragmentation. `serial` is deprecated. Identity is SQL standard.

### AD-002 — Soft Deletes
All tables use `deleted_at timestamptz`. No `DELETE` SQL allowed via RLS.
All queries filter `WHERE deleted_at IS NULL`. High-traffic tables get partial index.

### AD-003 — Standard Audit Columns
Every table: `id, created_at, updated_at, created_by, updated_by, deleted_at, is_active`
`created_by` and `updated_by` = `uuid references auth.users(id)` — nullable on first insert.

### AD-004 — Timestamps
`timestamptz` everywhere. Never plain `timestamp`. Avoids DST and timezone bugs.

### AD-005 — String Types
`text` not `varchar(n)`. Same storage, no artificial limits.
Exception: `text` with `CHECK (length(x) <= n)` if a business rule requires max length.

### AD-006 — RLS on Every Table
`ALTER TABLE x ENABLE ROW LEVEL SECURITY` + `ALTER TABLE x FORCE ROW LEVEL SECURITY`
Both statements required. FORCE prevents table owner from bypassing.

### AD-007 — RLS Function Caching
`(select auth.uid())` not `auth.uid()` — the subquery wrapper caches the call once per query.
Without it, Postgres calls `auth.uid()` for every row scanned. 100x+ difference on large tables.
Same applies to `(select auth.jwt()->'app_metadata'->>'role')`.

### AD-008 — Role Storage
Role stored in `auth.users.raw_app_meta_data->>'role'` (server-side only).
Never `user_metadata` — it is user-editable and unsafe for authorization.
Set via Supabase Admin API only (or trigger on first user creation).

### AD-013 — FK Indexes
Every foreign key column gets an explicit `CREATE INDEX`. Postgres does NOT auto-index FKs.
Missing FK indexes = slow JOINs + slow CASCADE deletes.

### AD-014 — Composite Index Column Order
Equality predicates first, range predicates last.
`WHERE status = 'x' AND created_at > '...'` → index on `(status, created_at)` not reversed.

### AD-015 — Partial Indexes for Soft Deletes
High-traffic tables: `CREATE INDEX ... WHERE deleted_at IS NULL`
Typically 95%+ rows are active. Partial index = 20x smaller, faster.

### AD-016 — Constraint Pattern
Use `DO $$ BEGIN IF NOT EXISTS ... END $$` for all constraint additions.
Postgres has no `ADD CONSTRAINT IF NOT EXISTS`. Without the guard, re-runs fail.

### AD-017 — Migration Files
Always `supabase migration new <descriptive_name>`. Never hand-craft filenames.
Timestamp prefix is generated by CLI. Hand-crafted timestamps cause ordering bugs.

## Business Logic

### AD-018 — Inventory Updates via Trigger Only
`stock_balances` is never updated directly by application code.
All updates go through `stock_transactions` insert → trigger updates `stock_balances`.
This enforces BR-002 and BR-003 at DB level, not just application level.

### AD-019 — Auto-Number Generation
All business document numbers auto-generated by DB trigger:
- Projects: `PP-YYYY-NNN`
- Material Requests: `MR-YYYY-NNNN`
- Issue Slips: `IS-YYYY-NNNN`
- Purchase Requisitions: `PR-YYYY-NNNN`
- Purchase Orders: `PO-YYYY-NNNN`
- MRN: `MRN-YYYY-NNNN`
- Suppliers: `SUP-NNN`

### AD-020 — BOQ Quantities Not Stored
Requested/Issued/Consumed/Returned/Wastage quantities are NOT stored in boq_items.
They are derived via views/queries from their source tables.
This prevents data inconsistency and eliminates sync issues.

### AD-021 — PR Consolidation
When shortage detected: check for existing open PR for same material.
If open PR exists → add to its items. If not → create new PR item.
Enforced in repository layer + DB function. Never create duplicate PRs (BR-014).

### AD-022 — Approval Threshold
Default PO approval threshold: ₹50,000 (configurable in app settings table).
PRs > ₹50,000 also require Owner approval.
Stored in `app_settings` table (key-value). Not hardcoded.

### AD-023 — Reserved Stock Mechanism
When MR is approved: `stock_balances.reserved_qty` increases.
When issue slip is created: `reserved_qty` decreases, `quantity` decreases.
`available_qty` = `quantity - reserved_qty` (computed, never stored).

## Flutter Architecture

### AD-009 — State Management
Riverpod with code generation (`@riverpod` annotation + `riverpod_generator`).
Pattern: `AsyncNotifier` for mutable state, `FutureProvider` for read-only.
No BLoC, no setState for business logic, no GetX.

### AD-010 — Navigation
Go Router with Shell Routes for the bottom navigation scaffold.
Route guards for role-based access. Redirect to login if unauthenticated.

### AD-011 — Data Models
Freezed + JsonSerializable. All models are immutable.
Models live in `data/models/`. Domain entities in `domain/entities/` (if different from model).
For this project: model = entity (no separate mapping needed — Supabase returns flat JSON).

### AD-012 — No Direct Supabase Calls from UI
Data flow is strictly: `Screen → Provider → UseCase → Repository → Supabase`
Providers call UseCases. UseCases call Repositories. Repositories call Supabase client.
Never `supabase.from()` inside a Widget or Provider build method.

### AD-024 — PDF Storage
Generated PDFs uploaded to Supabase Storage.
Bucket: `documents` (with folder structure by document type).
Issue slips: `/issue-slips/{year}/{slip_number}.pdf`
URL saved to database. Never re-generate if URL exists.

### AD-025 — Realtime Subscriptions
Only subscribe to tables that need live updates:
- `notifications` table (all roles)
- `stock_balances` (store role)
- `material_requests` (engineer + store)
- `approval_workflows` (owner + admin)
All other data uses pull-to-refresh or invalidate on action.

## UI

### AD-026 — Dark Theme Only
No light theme. This is an industrial ERP used on-site.
Dark theme = better readability in sunlight, professional appearance.
Use exact tokens from UI_SPEC.md.

### AD-027 — Currency Formatting
Indian number format: ₹12,50,000.00 (not ₹1,250,000.00)
Use `NumberFormat('#,##,##0.00', 'en_IN')` from `intl` package.
Compact: ₹12.5L for dashboard KPIs, full format in forms and reports.

### AD-028 — Status Colors
Status → Color mapping is centralized in `AppColors.statusColor()`.
Never hardcode status colors in individual widgets.
